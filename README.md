# Моковые автотесты для ТестОпс

Автономный пример на Python и pytest. Тесты проверяют локальную модель магазина,
не выполняют HTTP-запросов и не обращаются к базам данных или другим сервисам.
Интеграция рассчитана на цепочку:

`ТестОпс → GitHub Actions → pytest → allurectl → ТестОпс`.

## Что проверяется

- расчёт корзины и скидок;
- объединение одинаковых товаров и валидация количества;
- успешное и отклонённое оформление заказа через `unittest.mock`;
- матрица прав для пользовательских ролей.
- отдельный демонстрационный набор со статусами Passed, Failed, Broken, Skipped
  и XFail.

Все проверки имеют Allure-иерархию, названия, шаги, важность, владельца, слой,
компонент и теги. В ТестОпс результаты группируются по `parentSuite/suite` и
`epic/feature/story`. При первом полноценном запуске ТестОпс создаст по
результатам автоматизированные тест-кейсы.

Демонстрационные `failed` и `broken` тесты падают намеренно. Поэтому полный
прогон будет отмечен как неуспешный, одновременно показывая разные результаты
в GitHub и ТестОпс. Это не дефекты тестового проекта.

## Локальный запуск

Требуется Python 3.11 или новее.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install .
python -m pytest --alluredir=allure-results --clean-alluredir
```

Ожидаемый итог полного демонстрационного прогона:

```text
16 passed, 2 failed, 1 skipped, 1 xfailed
```

В Allure и ТестОпс два pytest-падения разделятся на `Failed` (ошибка проверки)
и `Broken` (техническая ошибка выполнения).

Чтобы получить полностью зелёный прогон без наглядных статусов:

```powershell
python -m pytest -m "not demo" --alluredir=allure-results --clean-alluredir
```

Для быстрого запуска только smoke-набора:

```powershell
python -m pytest -m smoke --alluredir=allure-results --clean-alluredir
```

Папка `allure-results` содержит готовые сырые результаты. Если локально
установлена Allure CLI, HTML-отчёт можно открыть командой:

```powershell
allure serve allure-results
```

## GitHub Actions до подключения ТестОпс

Workflow `.github/workflows/pytest-testops.yml` запускается вручную через
**Actions → Pytest mock tests to TestOps → Run workflow**. Пока параметры ТестОпс
не настроены, тесты выполняются автономно, а `allure-results` и JUnit XML
прикладываются к запуску GitHub как artifact на 14 дней.

## Подключение GitHub к ТестОпс

Когда будут известны GitHub-репозиторий и инстанс ТестОпс:

1. В настройках GitHub-репозитория создать Actions variable
   `ALLURE_ENDPOINT` со значением вроде `https://testops.example.ru`.
2. Создать Actions variable `ALLURE_PROJECT_ID` с числовым ID проекта.
3. Создать Actions secret `ALLURE_TOKEN` с API-токеном пользователя ТестОпс.
4. В администрировании ТестОпс добавить интеграцию GitHub и подключить её к
   нужному проекту.
5. Один раз вручную запустить workflow. После загрузки результатов джоба
   появится в разделе **Джобы** проекта ТестОпс.
6. В настройках джобы включить **Джоба может быть использована для запуска
   тестов** и связать её с настроенным подключением GitHub.
7. В ТестОпс создать глобальную переменную окружения с точным именем `Branch`,
   добавить её в параметры джобы и указать ветку репозитория, например `main`.

`ALLURE_JOB_RUN_ID` и `ALLURE_USERNAME` уже объявлены в `workflow_dispatch` как
необязательные служебные параметры. ТестОпс заполняет их сам. Не добавляйте в
джобу параметры, которых нет в `workflow_dispatch`: GitHub отклонит такой запуск
с ошибкой 422.

После настройки workflow автоматически выберет режим `allurectl watch`, будет
передавать результаты в ТестОпс и связывать запуск ТестОпс с запуском GitHub.

## Структура

```text
.github/workflows/pytest-testops.yml  # запуск из GitHub и передача результатов
src/mock_autotests/shop.py            # автономная тестовая модель
tests/                                # pytest + Allure-тесты
pyproject.toml                        # зависимости и конфигурация pytest
```
